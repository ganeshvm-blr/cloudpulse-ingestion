CloudPulse

Lightweight AWS Observability System

A mini Datadog-style pipeline that converts AWS Lambda execution logs into structured metrics and computes latency percentiles (p50, p95, p99).

Problem

AWS Lambda logs are unstructured and scattered across multiple log lines, making it difficult to compute reliable metrics like latency distributions.

Architecture

Lambda → CloudWatch Logs → Ingestion Lambda → DynamoDB → CLI Analytics Engine

Key Design Principle

One Lambda invocation = One structured metric record

This eliminates log ambiguity and makes metrics deterministic.

Data Model (DynamoDB)

{
  pk: "SERVICE#lambda-name",
  sk: "TIME#timestamp#requestId",
  durationMs,
  billedMs,
  memoryMb,
  requestId,
  timestamp
}

Core Features

Event-driven ingestion Structured metrics CLI analytics engine Latency percentiles Serverless architecture

Tradeoffs

  • No real-time streaming (Kinesis missing)
  • No dashboards (CLI-based only)
  • Limited scalability for large workloads

Scaling Plan

  • Add Kinesis for ingestion buffering
  • Add pre-aggregation layer
  • Split hot vs cold storage
  • Introduce dashboard (Grafana / QuickSight)

Tech Stack

AWS Lambda CloudWatch Logs DynamoDB Node.js
