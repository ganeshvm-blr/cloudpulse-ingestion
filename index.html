CloudPulse

Lightweight AWS-native observability system that transforms Lambda execution logs into structured metrics and computes latency percentiles (p50, p95, p99).

Problem

AWS Lambda logs are fragmented and unstructured, making it difficult to compute reliable metrics like latency distributions.

Solution

CloudPulse converts every Lambda invocation into a structured event for deterministic analytics.

Why This Project Stands Out

  • Event-driven observability system design
  • Real-world AWS serverless architecture
  • Time-series data modeling in DynamoDB
  • Separation of ingestion and analytics layers
  • Deterministic metrics instead of log parsing

Architecture

Lambda → CloudWatch Logs → Ingestion Lambda → DynamoDB → CLI Analytics Engine Each stage transforms raw logs into structured events and metrics

Key Design Principle

One Lambda invocation = One structured metric record

System Insight

Observability systems should model events, not logs. Once data is structured at ingestion, all downstream analytics becomes deterministic.

Interview Explanation

  • Lambda generates logs
  • CloudWatch streams logs
  • Ingestion Lambda transforms data
  • DynamoDB stores events
  • CLI computes percentiles

30-Second Interview Pitch

CloudPulse is a lightweight observability system that converts AWS Lambda logs into structured events and computes latency percentiles (p50, p95, p99).

It uses an event-driven pipeline: ingestion normalizes logs, DynamoDB stores metrics, and a CLI computes analytics.

Key idea: one invocation = one metric record, removing log parsing complexity.
